你好,我是**万强**,目前在得物做资深中间件工程师,坐标杭州。主攻分布式系统、分布式存储和 AI Agent 工程,信奉"从零实现一遍才算真的懂"。

## 走过的路

- **2014** 浙江大学通信工程毕业
- **2014 - 2019** 华数传媒,运维工程师。从写发布系统和日志收集自动化开始,阴差阳错走进了工程这条路
- **2019 - 2021** 叽里呱啦,资深 Python 开发工程师。0 到 1 搭了覆盖售前售后的 CRM 平台,支撑 200 人客服团队
- **2021 至今** 得物,资深中间件工程师。最有代表性的项目是**自研分布式注册中心**:因为社区版 Nacos 定位不了线上故障根因,一不做二不休用 Go 重写了一套 —— Raft 存储节点 + 分片横向扩展 + proxy 网关,如今支撑 50 万节点注册、30 万 QPS 峰值,3 年零 P 级故障

平时也碰过 IM 协议(tinode 改造,日均千万消息)和一堆中间件 SDK。

## 业余在拆的东西

工作之外喜欢造轮子,理由很简单:只有亲手实现,才知道黑盒里到底发生了什么。

- **cube_db** —— 用 Zig 从零写的嵌入式 KV 存储引擎,LMDB 式纯 COW B-tree,无 WAL 崩溃安全,O(1) 恢复和 compact。有序写路径性能约为 LMDB 的 1/2.7
- **Violin** —— 用 Zig 一个月从零搭的 coding agent,Agent Loop / 多模型协议适配 / Tool System / 插件事件总线,全链路自己走了一遍
- **pyrocketmq** —— 纯 Python 的 RocketMQ SDK,不依赖 JVM

## 关于 AI Agent

日常开发里约 90% 的代码由 AI Agent 产出,但技术决策仍是我自己做:Agent 给错了方案是常事,我的工作更多变成了判断和纠偏。之所以专门去实现了一个 coding agent,也是想搞清楚自己每天用的工具底层到底怎么转的。

顺带一提,我们把 Agent 用进了注册中心的故障注入和每周演练——生产稳定性体系里它也顶上了岗。
